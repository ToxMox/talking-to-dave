Reply-formatting system for Claude Code

Talking to Dave: a glanceable reply contract for Claude Code

Claude Code answers in whatever shape it feels like, so you reread each reply hunting for what happened and what it wants from you. This page is a short set of formatting rules you paste into Claude Code once; after that every reply comes back in the same layout, using a small fixed set of emoji that always mean the same thing. Line 1 alone tells you what happened, how the work is going, and whether you are needed. Tick the features you want directly below, copy one prompt into Claude Code, and read the rest of the page whenever you feel like it. Built for ADHD-friendly visual anchoring, and for anyone who skims.

Line 1 of every reply
🚀 ☀️ 🙋 Importer revamp: parser stream launched; one decision needed below.
  • 🚀What happened. Launched, running in the background.
  • ☀️How it is going. On plan, no surprises.
  • 🙋Whether you are needed. Yes, one answer, at the bottom.

InstallInstall the plugin, then make it yours

Two commands install it, and the plugin keeps the contract in your user-scope ~/.claude/CLAUDE.md current from then on, so it governs every project on the machine. Tick options here to preview the result, then run /talking-to-dave:configure in a session to apply them for real. Everything regenerates live: rule numbering stays contiguous, the palette lists only enabled anchors, and disabled features leave no dangling references, in any combination. The rest of the page shows you what you just installed.

Contract options
Replaces "Dave" everywhere in the generated contract, including the section title, the input-label rule, and the decision-table rule. Remembered in this browser, so a later copy of this page starts with it already filled in.
Adds slot 2 to the line-1 cluster: on plan, minor bumps, or off plan. Turning it OFF drops those three rows from the palette and collapses the cluster to the remaining slots, with slot numbering and the cluster wording adjusted to match.
Adds the walk-away / soon / needed-now / finished slot and pins the footer to it. Turning it OFF removes the forecast, parked, and footer rows from the palette, and the footer rule keeps its plain wording: "Next up:" with what happens next when nothing is needed, "Done." when the arc closes, with no anchor glyphs.
Lets arcs of 3 or more steps render as a bullet list led by the done, running and failed anchors, plus block glyphs for a trend or a proportion. Turning it OFF keeps plain counts ("2 of 4 streams done") and nothing else.
Installs the complete three-file setup: the contract gains a surface-pointer clause pointing at the two measured reference docs the plugin ships. Leave it OFF for a self-contained contract that depends on no other files.
Keeps the fold rule and with it the fixed wrap-up section order (anchor line, counts, what changed, verification, fold plus reference detail, footer last). Turning it OFF removes that rule entirely and renumbers the rest.
Keeps the rule that multi-option questions render as a mini table with a literal ASCII token to answer with. Turning it OFF removes the rule, so options are described in prose instead.
Code changes fence as diff. A readout may borrow the same fence only when a red line genuinely must catch the eye, since a pass/fail checklist is a glyph-led list instead. Turning it OFF drops the diff-fence clause from the markdown rule; fenced blocks still name their language.
Adds the draw-the-shape rule: structures (flows, states, architectures) render as inline diagram widgets, and quantitative comparisons as real charts, on surfaces that support them. Turning it OFF keeps replies text-only, and the remaining rules renumber.
Adds the interaction rule: sliders and live controls for teaching, clickable forms for structured input, widget buttons for decisions rich enough to want icons or subtitles. Turning it OFF keeps every exchange plain text.
Policy for the pop-up question dialog (AskUserQuestion): reserved for blocking decisions, allowed whenever a small option set fits, or banned outright. The generated rule follows your pick, and a plugin hook enforces a ban live, with no settings edits needed.
Adds the global rule banning em-dashes and en-dashes across replies, code, docs, commits, and issues. Turning it OFF generates no rule about them at all, and the remaining rules renumber.

Turning WEATHER or FORECAST off collapses the cluster gracefully: slot numbering, rule text, and the palette all adjust.

Your name and ticks are saved in this browser, so a newer copy of this page opens with them already set.

⬇️ A read-only preview of the contract the plugin generates and maintains for you. Install once:

claude plugin marketplace add ToxMox/talking-to-dave
claude plugin install talking-to-dave@talking-to-dave

Then run /talking-to-dave:configure in any session to apply your ticks for real. Updating later is claude plugin update talking-to-dave: the next session start swaps the installed block exactly, and anything you keep outside its BEGIN and END markers survives untouched.

⬇️ For Claude chat, not Claude Code. Paste into claude.ai, Settings, then personal preferences. Chat reads nothing from disk, so it needs its own copy. In a session, /talking-to-dave:chat-preferences prints this same text from your saved config, ready to paste.

It is deliberately shorter, and an ethos rather than a rulebook (why).

Legend + walkthroughAnatomy of a reply

    
One live sample reply, asked two questions. Anchors answers "what does this glyph mean, and where does it land": pick one and the sample dims to just that spot, then rewrites itself, words and glyphs together, so the sentences always match the state you built. Structure answers "what is this part of a reply called": the same sample, spotlit region by region. Each slot remembers your last pick, so the sample stays one running fake task (an importer revamp) seen in whatever state you compose, and the bar under it reads your composed cluster back in plain English. This is the reference; there is no separate summary table.

RationaleWhy it works

    
    
      
  • Fixed anchors. The same information always lives in the same place: line 1 carries the mood, the progress line carries the count, and the needs-you answer is always the last thing, so the eye learns coordinates instead of re-scanning prose.
    • 
      
  • Reserved semantics. Each palette glyph has exactly one meaning, so reading a reply becomes recognition rather than comprehension.
    • 
      
  • Traffic-light color. Green means walk away, amber means attention, red means blocked, judgments your visual system makes preattentively, before conscious reading starts.
    • 
      
  • A closed palette. One meaning per glyph is what makes it scannable, not rarity. An anchor can appear again further down at exactly the same meaning; what must never happen is a second glyph competing for a meaning that is already taken.
    • 
    

  





  

    
The contractThe rules

    
Fifteen rules in four families, each with a tiny rendered example. Together they are the whole contract; the legend at the top supplies the glyphs. The badge on each card is that rule's number in the contract you install, so it renumbers live as you switch features on and off at the top of the page.

  


  

    
Anchors

    

      

        
1
Bottom line first

        
Line 1 opens with the anchor cluster, then the outcome or the ask, bold. Context never leads. A strong default rather than a mandatory prefix: ordinary conversation and tier-1 one-liners skip it.

        
🔎 ☀️ 🟢 The leak is in the pool: sockets are never returned on timeout.
Explanation and evidence follow. They never lead.

      

      

        
2
The footer: four states, always last

        
The final section of a substantive reply, never a buried question, always agreeing with the FORECAST slot. 🙋, 🔜, and 🏁 always close with their footer; only 🟢 may skip it, and only on a short reply whose body already says what's next, so a missing footer is itself a claim: nothing outstanding, nothing hidden. Needs-you items keep stable IDs, carry how long they have waited, and repeat as an answerable core (the ask, a short stakes summary, the option tokens with consequences) rather than verbatim; genuine depth moves to a linked file, and past roughly three pending items the older ones compress to one-line table rows. Blocking items wait indefinitely: a default is only ever a proposal, never auto-applied.

        
🙋 Needs you:
  1. Q1 (waiting 2 replies): rename the flag before release? Blocks the tag. (yes / no / suggest)
or, when a decision is approaching:
🔜 Nothing needed yet: the flag-name call arrives when CI goes green.
or, green light:
🟢 Next up: the soak test runs unattended; results follow when it reports.
or, closed:
🏁 Done. 💤 Later, if you want: a dark-mode pass on the dashboard.

      

      

        
3
Counts and progress lists

        
Multi-part work carries counts prefixed with ⏳; arcs of 3 or more steps become a bullet list led by a palette glyph, which gives three states in full-brightness text. A markdown checkbox list is right only where you want items visibly checked off, since it strikes through and dims them. Neither is related to any task-tracking tool the host may provide. Block glyphs cover the jobs a list cannot: a sparkline for a trend, a shade ramp for a proportion.

6
Input labels

        
Anything the reader must type or click sits alone in a fenced block with literal inputs labeled; the label line above the block starts with ⬇️. Shell commands are tagged bash, one command per block, no leading $, no interleaved output, because that is exactly what earns the Run button.

Structure

    

      

        
4
Length is guidance, not a box

        
Aim short (status updates a few lines, wrap-ups about a screenful), but never drop or over-compress load-bearing information to fit. When detail is reference material rather than decision material, put it in a local file under docs/, self-contained HTML when it wants styling, link the path so one click opens it in a pane, and leave a 2-3 line digest inline. A published artifact leaves the machine, so reach for one only when the reader asks for something shareable.

        
Profiler sweep done: the hot path is the locale lookup.
Full 200-row trace lives in reports/sweep.md; the digest above is the decision material.

      

      

        
5
One topic per bullet

        
Bold lead noun, final state not the journey, and reach for bullets by default: two or more parallel things become bullets, never one welded paragraph. Prose is for a single argument that has to flow, and bullets nest one level where a point genuinely carries sub-points, two only when the content is really a tree. IDs never appear bare: a mentioned ID carries a human hook, built into the ID itself or added beside it.

        
  • Cache key now includes the locale; collisions gone.
  • Flush endpoint added behind the admin scope (T-0142 flush-scope).
    • Old callers keep working; the unscoped route 410s.

      

      

        
9
Structural markdown

        
Two heading tiers anchor wrap-ups (status updates stay headerless): # is the loud one and ## the quiet one, while ### is indistinguishable from bold body text. Tables hold enumerable facts with numeric columns right-aligned, and they span the full pane, so two thin columns read as mostly whitespace. One > ⚠️ blockquote holds the load-bearing warning, and quotes nest properly when a quote inside a quote is real; ~~strikethrough~~ marks superseded content and nests inside bold correctly. A diff fence is for an actual diff, plus the rare readout where a red line must catch the eye; a real changeset belongs in the diff viewer, and a pass/fail checklist is a glyph-led list. Markdown checkbox lists render as real checkboxes rather than literal brackets, and footnotes render properly, the right home for an aside that would otherwise break a sentence. Numbered lists are reserved for true sequences; bullets otherwise. Link file paths rather than pasting them: the link hides the URL and one click opens the file, and the path is written as it appears from the working directory, since a ~/... or absolute form does not resolve to a clickable target. HTML tags never render, they print literally.

Reply tiers, and judgment above them

        
Tier 1, one-liner: a direct answer with nothing pending gets the answer alone, no cluster and no footer. Text hygiene

    

      

        
7
No em-dashes or en-dashes, global scope

        
Neither dash in any generated output: replies, code, comments, docs, commit messages, issue bodies, anything. Use a plain hyphen, a comma, parentheses, a colon, or a new sentence. (Both glyphs are banned from this very page, so the bad examples are spelled out.)

8
No time estimates

        
No time estimates and no time-of-day remarks; frame on risk and outcome instead.

Tweaking FAQ

  

    How do I change an emoji safely?
    
Keep one meaning per glyph. Pick a replacement that appears nowhere else in the palette, then update both the rule text and the palette list in the same edit, so the glyph never carries two meanings and no meaning has two glyphs. Prefer single-codepoint emoji (at most a presentation selector): tone-modified or ZWJ-joined emoji can split into two half glyphs on surfaces that measure codepoints instead of grapheme clusters.

  

  

    Can I add more emoji to the palette?
    
Resist it. The palette works because it is closed: every meaning has exactly one glyph, and every glyph exactly one meaning. If a new anchor is genuinely needed, give it exactly one meaning no other glyph carries, and keep decorative emoji out of the anchor slots entirely.

  

  

    Can I trial-run it in one project first?
    
Yes. Copy the Preview contract output into that project's own CLAUDE.md (in the repo root) instead of ~/.claude/CLAUDE.md. It then applies only to sessions in that project. When you like it, move the section to the user-scope file and delete the project copy.

  

  

    Why is the Claude chat version different?
    
The contract governs Claude Code, wherever it runs: the desktop app's Code tab, the terminal CLI, the editor extension, cloud sessions. Claude chat (the Chat tab, the web app, mobile) reads nothing from disk, so it needs its own copy pasted into your account settings.

    
It is deliberately not the same document. Chat is a different medium, with no repository to link into and no panes to open, and a different context: mostly conversation rather than work sessions. In a work session the likely failure is under-formatting, a wall of text with the answer buried, which rules fix. In chat the likely failure is over-formatting, ceremony on a two-line answer, which rules cause and judgment prevents. So that version is an ethos, and it ends by saying most messages need none of it.

  


  
Undo, in plain words

  
Run claude plugin uninstall talking-to-dave: hooks and skills go with it, and because the dialog policy is enforced by a hook rather than a settings edit, a banned AskUserQuestion dialog comes back on its own. Then open ~/.claude/CLAUDE.md and delete the section between the two presentation-contract marker comments; the plugin never deletes your file content for you. Saved choices sit in the plugin data directory under ~/.claude/plugins/data/, safe to delete. If you also pasted the chat ethos, clear that box in your claude.ai account settings.
